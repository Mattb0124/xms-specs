# XMS repository guide

XMS (Xelerated Managed Services) is the standalone ServiceNow replacement for the Hackett Digital Managed Services practice. This repository holds the specification set and the two applications.

## Layout

| Path | What it is |
|---|---|
| `00-overview/`, `01-architecture/`, `02-modules/`, `03-delivery/` | The specification set. Start at `README.md`; **open questions are in `00-overview/CLARIFICATIONS-NEEDED.md` and block work in seven modules**; decisions are in `00-overview/DECISION-LOG.md`; the requirement register is generated by `00-overview/scripts/build_register.py` and never hand-edited. |
| `frontend/` | The Next.js and React application (deployable `xms-web`): internal desk at `xms.<domain>` and the client portal at `portal.<domain>`. Design tokens under `frontend/styles/tokens`, the Axel streaming client under `frontend/lib/axel-client`, Playwright under `frontend/e2e`. |
| `backend/` | The NestJS application (deployable `xms-api`) and the worker as a second entrypoint (`backend/src/worker`). Domain rules in `backend/src/domain`, Drizzle schema and migrations in `backend/src/db`, DTOs and the permission catalog in `backend/src/contracts`, test kit in `backend/test/kit`. |
| `.claude/rules/xms/` | Always-loaded repository rules: `security-first.md` (ADR-16). |
| `.claude/skills/` | Skills for the spec repo itself: `triage-ticket` (the ClickUp triage decision procedure) and `xms-security-first` (the security definition of done, also copied into both apps). |
| `frontend/.claude/skills/`, `frontend/.cursor/skills/` | The 19 skills that ship with the frontend repo: `xms-security-first`, `review-changes`, `improve-review`, `xms-web-design-system`, `xms-web-ui-component`, `xms-web-data-table`, `xms-web-data-endpoint`, `no-hardcoded-styling`, `web-taste`, `typescript`, plus the shared set (`xms-write-spec`, `xms-write-what-was-done`, `xms-git-development-workflow`, `writing-tests`, `todo-discipline`, `commit-at-point`, `create-skill`, `skill-authoring`, `aibl-clickup`). `.cursor/skills` is a byte-identical mirror. Curated skill provenance is in `frontend/skills-lock.json`. |
| `backend/.claude/skills/`, `backend/.cursor/skills/` | The 14 skills that ship with the backend repo: `xms-security-first`, `review-changes`, `improve-review`, `secure-endpoint-auth`, `typescript`, plus the same shared set. `.cursor/skills` is a byte-identical mirror. Curated skill provenance is in `backend/skills-lock.json`. |
| `frontend/.claude/commands/`, `backend/.claude/commands/` | Slash commands, per app: `pre-pr-quality-check` in both (each running its own gates), `create-rtk-query-api-slice` in the frontend, `create-nestjs-feature-module` in the backend. |

The two applications are separate deployables and separate git repositories (`frontend/` is github.com/Mattb0124/xms-frontend, `backend/` is github.com/Mattb0124/xms-backend, both cloned into this folder) with their own `package.json`, lockfile, Dockerfile and pipeline stage. There is no workspace tooling joining them (ADR-12, ADR-14); the frontend consumes the backend through its OpenAPI document and generated types.

## Rules that override defaults here

- **Security first (ADR-16).** Every change is built to pass security audits: load the `xms-security-first` skill before designing, coding or reviewing; the always-on rule is `.claude/rules/xms/security-first.md`; controls and evidence are mapped in `01-architecture/SECURITY-ASSURANCE.md`. A pull request without the completed security checklist is not reviewed.

- Product name is XMS; "DMS" is the practice, never the product (ADR-13).
- No em-dashes in any document or user-facing copy; absolute dates only.
- Every account-scoped table carries `account_id` with forced row-level security; tenancy is bound in the data layer, never passed as an optional parameter (ADR-02, `01-architecture/DATA-MODEL.md` §3).
- The server is the only author of SLA due times, breach latches, derived priority, burn-down and permissions; the browser renders and counts down.
- All AI calls go through the Axel adapter; nothing else holds a harness credential (`01-architecture/AI-INTEGRATION.md`).
- Lint, `tsc --noEmit`, unit, integration and the isolation suite gate every build; `ignoreBuildErrors` and `ignoreDuringBuilds` are forbidden.
- Before a pull request run the `pre-pr-quality-check` command in the app you changed.

## Skills

The skills in each app are XMS-native: AIX vocabulary and paths were rewritten when they were adopted into the two repos on 2026-09-04 (`web-ui` to `frontend`, `app-api` to `backend`, `api/v3/*` to `/v1/*`, `org_slug` and `tenantSlug` to the XMS `Principal` and `account_id`, spec paths to `02-modules/<module>/`, and the `aix-*` slugs to `xms-*`). Skills that were AIX-specific were rewritten against the XMS specs rather than ported: `secure-endpoint-auth` against `01-architecture/SECURITY-AND-TENANCY.md`, `writing-tests` and both `pre-pr-quality-check` commands against `03-delivery/TEST-STRATEGY.md`, and the four `xms-web-*` skills against `01-architecture/DESIGN-SYSTEM.md`.

`typescript`, `skill-authoring` and `web-taste` are vendored from `pproenca/dot-skills` and are left as upstream ships them; do not hand-edit those, update them through the installer and the per-app `skills-lock.json`.

Two things the AIX originals got wrong for XMS, now corrected in place and worth not reintroducing: the web app tests with **Vitest**, not Jest (the backend is Jest), and the shell and dense-list rules come from the **v2 wireframes** (`01-architecture/WIREFRAMES.md`, ADR-17): navy finder bar, pinned sidebar, IBM Plex Mono for keys, **no row striping** (the POC's zebra was overridden on 2026-09-05).
